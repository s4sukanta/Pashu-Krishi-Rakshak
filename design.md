# Pashu-Krishi Rakshak: System Design Document

## 1. High-Level Architecture
The system follows a **"Thick Client + GenAI Brain"** architecture. To adhere to the constraint of using *only* AWS Bedrock and Amazon Q (no Lambda/API Gateway), the heavy lifting of media processing is moved to the client device, which communicates directly with the Bedrock Runtime API.

### Architecture Diagram
*(Please refer to the architecture_diagram.png included in the repo)*

**Core Components:**
1.  **Edge Device (Client):** Captures video/audio, performs frame extraction using OpenCV, and handles Speech-to-Text conversion.
2.  **AWS Bedrock (Server):** The monolithic intelligence engine hosting the Foundation Model and Knowledge Base.
3.  **Amazon Q (Developer):** The generative coding assistant used to build the client script and configure IAM roles.

---

## 2. Component Design

### 2.1 The Client (Edge Processing)
* **Technology:** Python Script (generated by Amazon Q).
* **Responsibilities:**
    * `input_capture()`: Opens camera/mic.
    * `media_processing()`: Uses `cv2` to extract 3 frames (start, middle, end) from video.
    * `payload_builder()`: Encodes images to Base64 and wraps text context into a JSON object.
    * `api_caller()`: Uses `boto3.client('bedrock-runtime')` to invoke the model.

### 2.2 The Brain (AWS Bedrock)
* **Model ID:** `anthropic.claude-3-sonnet-20240229-v1:0`
* **Role:** Multimodal Reasoning.
* **System Prompt:**
    > "You are an expert Veterinary AI. Analyze the provided images and text context. Search the Knowledge Base for confirmed treatments. Output a diagnosis and prescription in simple language."

### 2.3 The Memory (RAG)
* **Service:** Bedrock Knowledge Base.
* **Data Sources:**
    * `Indian_Veterinary_Index.pdf`
    * `Crop_Pest_Management_Guide.pdf`
* **Vector Store:** OpenSearch Serverless (Managed by Bedrock).

---

## 3. Data Flow

1.  **User Action:** Farmer records video + speaks symptoms.
2.  **Client Processing:**
    * Video -> Extracted Frames (Images).
    * Audio -> Text Transcript.
3.  **API Request:** Client sends `InvokeModel` request to AWS Bedrock.
    * Payload: `{ "messages": [ { "image": "base64..." }, { "text": "transcript..." } ] }`
4.  **Model Inference:**
    * Claude 3.5 Sonnet analyzes visual clinical signs.
    * Claude 3.5 Sonnet correlates visuals with text context.
5.  **Knowledge Retrieval:** Model queries Knowledge Base for specific medicine dosage.
6.  **Response:** Bedrock returns JSON `{ "diagnosis": "...", "cure": "..." }`.
7.  **User Output:** Client uses Text-to-Speech to play the cure.

---

## 4. API Contract (Direct-to-Bedrock)

**Endpoint:** `bedrock-runtime.invoke_model`

**Request Body:**
```json
{
  "anthropic_version": "bedrock-2023-05-31",
  "max_tokens": 1000,
  "messages": [
    {
      "role": "user",
      "content": [
        {
          "type": "image",
          "source": { "type": "base64", "media_type": "image/jpeg", "data": "<base64_string>" }
        },
        {
          "type": "text",
          "text": "Context: Cow has high fever. Diagnose and prescribe."
        }
      ]
    }
  ]
}
